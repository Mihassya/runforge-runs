# Runforge — Runs

Страница **Runs** для Runforge: список запусков AI-агентов с поиском, фильтром по статусу, сортировкой и панелью с подробностями запуска. Тестовое задание Junior Frontend Developer.

Стек: React 19, TypeScript, Vite, CSS Modules, React Router (только для параметров URL). Данные берутся из локального mock-сервиса.

## Запуск

Нужен Node.js 20.19+ или 22.12+.

```bash
npm install
npm run dev
```

Приложение откроется на http://localhost:5173.

| Команда                | Что делает                               |
| ---------------------- | ---------------------------------------- |
| `npm run dev`          | dev-сервер                               |
| `npm test`             | тесты (Vitest)                           |
| `npm run test:watch`   | тесты в режиме наблюдения                |
| `npm run build`        | проверка типов (`tsc`) и сборка в `dist` |
| `npm run preview`      | просмотр собранной версии                |
| `npm run lint`         | линтер (oxlint)                          |
| `npm run format:check` | проверка форматирования (Prettier)       |

## Что умеет

- **Список запусков**: название, id, репозиторий и ветка, статус, дата создания и длительность. На широком экране — таблица, на узком (до 860 px) — карточки.
- **Фильтр по статусу**: All, Queued, Running, Succeeded, Failed. Активный фильтр залит тёмно-синим, у каждой кнопки — счётчик запусков.
- **Поиск** по названию запуска или репозиторию, без учёта регистра. Работает вместе с фильтром: счётчики на кнопках статусов учитывают поисковый запрос.
- **Сортировка**: сначала новые, сначала старые, по длительности (запуски без длительности — в конце).
- **Детали запуска** в выезжающей справа панели: статус, ветка, даты, длительность, результат и логи. На телефоне панель занимает весь экран.
- **Состояния**: skeleton при загрузке, ошибка с кнопкой «Retry», пустой результат с кнопкой «Reset filters».
- **Статусы** различаются не только цветом: у каждого есть текстовая подпись, у Queued полая точка, у Running — пульсирующая.

### Состояние в URL

Фильтр, поиск, сортировка и открытый запуск хранятся в параметрах адреса, поэтому ссылкой можно поделиться, а состояние переживает перезагрузку:

```
/?status=failed&q=api&sort=longest&run=run_29ad
```

Открытие деталей добавляет запись в историю браузера: кнопка «Назад» закрывает панель. Смена фильтров и поиска заменяет текущую запись, чтобы не засорять историю.

### Как увидеть каждое состояние

- **Загрузка** — mock-запрос отвечает через 0,9 с, skeleton виден при каждом открытии.
- **Ошибка** — открыть http://localhost:5173/?fail=1. Первый запрос завершится ошибкой, «Retry» загрузит данные.
- **Пустой результат** — ввести в поиск, например, `zzz`.
- **Неизвестный запуск** — открыть `/?run=run_missing`: панель сообщит, что запуск не найден.

### Клавиатура

- `/` — перейти в поиск.
- `Tab` по строкам списка, `Enter` — открыть детали.
- `Esc` — закрыть детали; фокус возвращается на строку, с которой их открыли.

## Тесты

```bash
npm test
```

Vitest + React Testing Library, окружение jsdom. Тесты страницы рендерят всё приложение и действуют как пользователь: кликают по кнопкам, печатают в поиск и ищут элементы по ролям и подписям, как их видит скринридер. Mock-сервис в тестах подменён: данные приходят сразу, без задержки, из небольшого набора в `src/test/fixtures.ts`.

Три сценария из задания (`src/pages/RunsPage.test.tsx`):

- **Фильтрация по статусу** — после клика по «Failed» кнопка активна и в списке только запуски со статусом Failed.
- **Поиск** — по репозиторию, по названию без учёта регистра и вместе с фильтром по статусу.
- **Открытие деталей** — клик по строке открывает панель с результатом и логами, «Close» возвращает к списку.

Дополнительно проверяются загрузка, ошибка с «Retry», пустой результат со сбросом фильтров, восстановление фильтра и открытого запуска из URL. Ещё есть тесты чистых функций в `src/lib`: фильтрация, сортировка, форматирование даты и длительности.

jsdom не умеет `showModal()` и `close()` у `<dialog>`, поэтому в `src/test/setup.ts` для них есть упрощённая замена.

## Как проверял вручную

Сценарии проверены в Chrome на ширине 1440, 1280, 800 и 360 px:

1. **Фильтр по статусу.** «Failed» оставляет 2 запуска со статусом Failed, кнопка выделена, в URL появляется `status=failed`.
2. **Поиск.** `payments` находит 3 запуска этого репозитория, `auth` — «Auth refactor». Поиск `payments` + фильтр «Failed» дают пустой результат; «Reset filters» возвращает все 9 запусков и очищает поле.
3. **Детали.** Клик или `Enter` на строке открывает панель с логами и результатом; закрывается кнопкой «Close», `Esc`, кликом по фону и кнопкой «Назад» в браузере.
4. **Ошибка.** С `?fail=1` показывается сообщение и «Retry»; после повтора список загружается.
5. **Без длительности и результата.** У Queued и Running вместо длительности прочерк, в деталях — «Not started yet» / «Still running» и пояснение вместо результата.
6. **Мобильная вёрстка.** На 360 px нет горизонтальной прокрутки, список показан карточками.

В консоли браузера нет ошибок и предупреждений.

## Решения

- **Детали в drawer, а не на отдельной странице.** Список и фильтры остаются на месте, и не нужно заново загружать данные при возврате. Drawer построен на нативном `<dialog>`: `showModal()` сам удерживает фокус внутри панели и возвращает его после закрытия. Источник правды — параметр `?run=` в URL.
- **Логика отдельно от компонентов.** Фильтрация, сортировка и форматирование — чистые функции в `src/lib`, их легко читать и проверять.
- **Без UI-библиотек и стейт-менеджеров.** Данных мало: хватает `useState` и параметров URL.
- **Стиль** — по мотивам runforge.space: молочный фон `#f4f1eb`, тёмно-синий `#081a33`, шрифты Inter и IBM Plex Mono. Все значения — CSS-переменные в `tokens.css`, отступы кратны 4 px.
- **Даты** приходят в ISO (UTC) и показываются в часовом поясе пользователя через `Intl.DateTimeFormat`.
